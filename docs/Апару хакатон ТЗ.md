**Проект: QR-сервис заказа такси APARU**

**1\. Общая цель проекта**  
Разработать **web-приложение для быстрого заказа такси через QR-код**, интегрированное с сервисом APARU.  
Система должна позволять пользователю заказать такси **в один клик**, отсканировав QR-код, без необходимости вручную вводить адрес или проходить сложную регистрацию.  
Платформа должна:

* расширить аудиторию сервиса APARU за счет использования QR-технологий;  
* упростить процесс заказа такси;  
* повысить количество заказов;  
* увеличить узнаваемость бренда APARU.

Основная идея решения — **заказ поездки через QR-код**, размещенный в общественных местах.

**2\. Целевая аудитория**  
Пользователи системы:

1. Пассажиры такси  
2. Пользователи, находящиеся в общественных местах (ТРЦ, аэропорты, вокзалы, кафе и т.д.)  
3. Новые пользователи сервиса APARU  
4. Водители сервиса APARU

**3\. Основной функционал**  
**3.1 Сканирование QR-кода**  
Пользователь сканирует QR-код, размещенный в определенной точке.  
После сканирования:

* открывается web-приложение;  
* автоматически определяется точка отправления (точка «А»);  
* пользователь получает информацию о поездке.

QR-код должен содержать:

* идентификатор точки  
* координаты точки  
* ссылку на web-приложение.

**3.2 Информация о поездке**  
После сканирования QR-кода пользователь должен видеть:

* информацию о водителе  
* информацию об автомобиле  
* тариф поездки  
* способ оплаты  
* кнопку подтверждения заказа

Интерфейс должен быть максимально простым и понятным.

**3.3 Подтверждение номера телефона**  
Перед созданием заказа пользователь должен:

* подтвердить номер телефона  
* получить SMS-код  
* ввести код подтверждения

После подтверждения номер привязывается к заказу.

**3.4 Создание заказа**  
После подтверждения номера:

* система формирует заказ;  
* заказ отправляется в систему такси;  
* ближайший водитель получает заявку.

Параметры заказа:

* точка А — определяется по QR-коду  
* точка B — может быть введена пользователем  
* тариф  
* способ оплаты.

**3.5 Отображение статуса заказа**  
Пассажир должен видеть статус поездки:

* поиск водителя  
* водитель назначен  
* водитель прибыл  
* поездка началась  
* поездка завершена.

Дополнительно отображается:

* имя водителя  
* автомобиль  
* номер машины  
* время прибытия.

**3.6 Повторное сканирование**  
Система должна поддерживать **повторное сканирование QR-кода** без необходимости повторной регистрации пользователя.  
Пользователь должен иметь возможность быстро оформить новую поездку.

**3.7 CTA для установки приложения**  
После завершения заказа пользователю предлагается:

* установить мобильное приложение APARU;  
* перейти в App Store / Google Play.

Это должно способствовать **росту пользователей мобильного приложения**.

**4\. Архитектура решения**  
Решение должно быть разработано с учетом **масштабируемости**.  
Система должна:

* поддерживать большое количество пользователей;  
* быть готовой к масштабированию;  
* обеспечивать стабильную работу при высокой нагрузке.

**5\. Преимущества решения**  
Преимущества предлагаемого подхода:

* устойчивость к ошибкам GPS при определении точки «A»  
* быстрый заказ такси через QR  
* минимальное количество действий пользователя  
* масштабируемая архитектура системы  
* возможность размещения QR-кодов в любых локациях
